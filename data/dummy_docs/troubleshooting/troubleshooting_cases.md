# トラブルシュート事例集

過去の問い合わせ対応から、症状・原因・対処法をまとめた事例集です。

## 事例1: SSO連携後にログインできなくなった

**症状**: Microsoft Entra ID とのSSO連携を有効化した直後から、全ユーザーがログインできなくなった。

**原因**: SSO設定時に緊急ログインアカウントを残さずに全ユーザーのパスワードログインを無効化したため、IdP側のメタデータ設定に軽微な不備（証明書の有効期限切れ）があった際に、誰もシステムにアクセスできない状態に陥った。

**対処**: サポート窓口にテナントIDを連絡し、緊急措置としてシステム管理者アカウント1件のみパスワードログインを一時的に復旧してもらった。復旧後、IdP側の証明書を更新し、以後は緊急ログインアカウントを最低1つ維持する運用に変更した。

## 事例2: 在庫アラートが特定カテゴリの品目でのみ届かない

**症状**: 「消耗品」カテゴリの品目のみ、発注点を下回ってもアラートメールが届かない。他のカテゴリでは正常に届いていた。

**原因**: 「消耗品」カテゴリが品目マスタ一括インポート時に自動生成されたカテゴリであり、担当者グループの割り当てが行われていなかった。

**対処**: 「在庫管理 > カテゴリ設定」で「消耗品」カテゴリに担当者グループを割り当てたところ、以後正常にアラートが届くようになった。品目一括インポートを行う際は、事前に全カテゴリへの担当者グループ割り当てを確認する運用手順を追加した。

## 事例3: 月次締め処理が「未検収発注あり」で進まない

**症状**: 月末に会計締め処理を実行しようとすると「未検収の発注が存在します」というエラーで処理が止まる。

**原因**: 3か月前に作成した発注のうち1件が、仕入先の廃業により納品されないまま「発注済み」ステータスで放置されていた。

**対処**: 購買担当者が該当発注を「取消」ステータスに変更し、会計側の未検収発注チェックから除外されることを確認したうえで締め処理を再実行し、正常に完了した。長期間ステータスが更新されない発注を検出する月次レポートを新設し、再発防止とした。

## 事例4: 棚卸確定後に差異調整仕訳が起票されない

**症状**: 在庫管理モジュールで棚卸を確定したが、会計モジュールに差異調整仕訳の候補が表示されない。

**原因**: 品目マスタ登録時に「原価区分」を会計側の勘定科目にマッピングしていなかったため、棚卸差異があっても仕訳連携の対象外として扱われていた。

**対処**: 品目マスタの原価区分マッピングを設定し、棚卸イベントを再実行不可のため、当月分は会計担当者が手動で差異調整仕訳を起票した。翌月以降は自動連携が正常に機能することを確認した。品目マスタ登録時のチェックリストに「原価区分マッピングの設定」を追加した。

## 事例5: 発注承認が特定部門でのみ滞留する

**症状**: ある拠点の部門でのみ、発注申請が「承認待ち」のまま何日も進まない状態が発生した。

**原因**: 直前に実施した組織階層の再編で、当該部門の部門長が新しい部門コードに正しく引き継がれておらず、承認者が誰にも割り当てられていない状態になっていた。

**対処**: 「設定 > 組織構造」で当該部門の部門長を再設定し、承認ルートを復旧させた。組織階層を変更した際は、必ずテスト申請で承認ルートが正しく機能するかを確認する手順を、初期設定ガイドのチェックリストに明記した。
