# Step 5: 簡易チャットUI（Streamlit）

関連Issue: #1

## スコープ

Step 4で実装した`generate_answer`を使い、業務担当者が実際に質問できる簡易チャットUIをStreamlitで構築する。
検証観点の一つ「業務担当者が迷わず操作をナビゲートされる」というUX要件に対し、回答精度以外に必要な
設計（質問例の提示、引用元の分かりやすい提示、エラー時の振る舞い）を意識した。

## 実装物

- `src/app/formatting.py`: 引用元リストをMarkdown箇条書きに変換する`format_citations_markdown`
  （Streamlit非依存の純粋関数。単体テスト対象）
- `src/app/streamlit_app.py`: チャットUI本体
  - サイドバー: セッションID表示、「新しい会話を始める」ボタン（セッションIDと画面上の履歴をリセット。
    Cosmos DB側の旧セッションデータはそのまま残る）、質問例ボタン3種
  - メイン画面: `st.chat_message`によるユーザー/アシスタントの吹き出し表示、回答直後に
    「引用元を表示」の`st.expander`で出典を提示
  - `generate_answer`呼び出しを`try/except`で囲み、失敗時はエラーメッセージをチャット上に表示する
    （アプリ全体がクラッシュしてブランク画面になることを避ける）
  - Azureクライアント群は`st.cache_resource`でセッション間キャッシュし、質問のたびに再接続しない

## UX設計判断（「回答精度以外に必要な設計」）

- **質問例ボタン**: 初見の業務担当者は「何を聞けばいいか分からない」状態で離脱しうるため、
  代表的な質問3つをワンクリックで試せるようにした
- **引用元は既定で折りたたみ**: 回答本文を主役にしつつ、根拠を確認したい場合はすぐ展開できる
  ようにした（常時展開だと画面が長くなり、業務担当者が本文を読みにくくなるため）
- **エラー時もチャットとして表示**: 例外発生時に画面がクラッシュ・ブランク化すると、
  業務担当者は「壊れた」と誤解して離脱しやすい。エラーもアシスタントの発言として表示し、
  会話の流れを保つようにした

## テスト方針

`format_citations_markdown`は純粋関数のため単体テストしている。Streamlit UI本体は
自動テストの対象外とし、`playwright`によるヘッドレスブラウザ操作で実際に起動・操作して
動作確認した（下記「動作確認」参照）。

```bash
uv run pytest tests/test_formatting.py -v
```

## 動作確認（2026-09-06）

```bash
uv run streamlit run src/app/streamlit_app.py --server.headless true
```

Playwright(Node.js版, ヘッドレスChromium)で以下を確認した。

- 初期表示: サイドバーにセッションID・「新しい会話を始める」ボタン・質問例3件が表示される
- `st.chat_input`から実際に質問を送信し、Azure OpenAI/AI Searchを介した回答と
  「引用元を表示」エキスパンダーが表示される（引用元にタイトル重複がないことも目視確認、
  PR #5での修正が反映されている）
- サイドバーの質問例ボタンをクリックしても同様に質問が送信され、回答が返る
- 「新しい会話を始める」ボタンをクリックすると、セッションIDが新しいものに変わり、
  画面上の会話履歴がクリアされる
- ブラウザコンソール・ページエラーは検出されなかった
